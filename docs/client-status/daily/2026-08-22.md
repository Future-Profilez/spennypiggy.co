**Bugs found and fixed while building** (each was live before today):

- Refunding real money wrote **no audit trail**; changing a task purchase's *date* did.
- The push fan-out ran **inside the web request**, against a 60-second Lambda timeout — a creator with a few hundred supporters would have timed out mid-send with the row already marked sent.
- "Popular" ranked by **transactions, not people** (`source_id` is the payment morph, not the supporter).
- **The bio page's Unlock did nothing.** Every refusal in the wish checkout answers with `redirect()->back()`, and a supporter arriving from a bio card has no meaningful "back" — so they landed on the homepage carrying a flash message. And **no layout rendered a flash at all**: only fifteen pages read it, five of which toasted it. Every `->with('error', …)` in the app outside those five was written and thrown away.
- The **high-value guest gate was asked with a hardcoded amount of 0**, so the "above this, you need an account" half could never fire on that path.
- **33 inline box-shadows** survived the no-shadow sweep because the scanner only looked at classes and CSS files, never at JS style objects.
- The two newest **paid-ads pages were missing from the sitemap** — the two about to carry ads.

## Security ticks

- **Enhanced Audit Logs (§E) — Stripe half closed.** Every refund writes attempt → succeeded/failed on one correlation id, with the attempt recorded **before** the Stripe call: a timeout after Stripe created the refund would otherwise log a failure for money that actually moved.
- **Creator push shipped with its guards, not after them** — no links, usernames, email addresses or phone numbers may appear in a notification. A push arrives on a lock screen with a creator's name on it and is trusted accordingly; a link in one is how a paying audience gets moved somewhere with no refunds and no moderation.
- **Nothing in the moderation path can be edited or deleted** — the admin screen is read-only for the record and can only add a flag, with a reason.
